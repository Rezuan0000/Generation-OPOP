# Генерация документа ОПОП (Flask + JSON + Word)

Веб-приложение на **Flask**: загрузка выгрузки базы в **JSON** (файл или URL), выбор направления подготовки и года, сбор полей для шаблона, генерация **ОПОП.docx** по `template.docx`, предпросмотр в браузере и (при наличии меток в шаблоне) ввод полей `{{MANUAL:…}}` перед финальной сборкой.

Отдельно остаётся скрипт **`generate_opop.py`**: подстановка меток в Word без веб-части (удобно для отладки шаблона).

## Структура проекта

| Файл / папка | Назначение |
|--------------|------------|
| `app.py` | Flask: маршруты, загрузка JSON, генерация, предпросмотр, скачивание |
| `json_data_extractor.py` | Разбор JSON с ключом `tables`, `build_opop_data`, загрузка по URL (`fetch_db_json`) |
| `api_export.py` | Сборка и POST исходящего JSON в API |
| `generate_opop.py` | Подстановка `{{ключей}}`, динамические таблицы, `{{MANUAL:…}}` |
| `template.docx` | Шаблон ОПОП (рядом с `app.py`) |
| `templates/` | HTML-шаблоны интерфейса |
| `instance/` | Создаётся при работе приложения: загрузки и результаты (в git не коммитится) |
| `opop_defaults.json` | Необязательно: переопределение длинных текстов (области 06/40, виды деятельности, формулировки `prof_standard_*`), если в выгрузке API нет нужных строк |

Данные для блоков «профстандарты», «виды деятельности» и связанных полей берутся из выгрузки API по выбранному **учебному плану** (`title_plan.id`): таблицы **`title_plan_prof_standards`** и **`title_plan_activities`**. Если для плана строк нет, используется встроенный запасной набор (и в `opop_data.json` в `_missing_fields` появляются поясняющие маркеры). Файл `opop_defaults.json` позволяет задать тексты без правки кода.

## Требования

- Python 3.10+ (в проекте также использовался 3.13)
- Установка зависимостей:

```bash
pip install -r requirements.txt
```

- Установленный **Pandoc** (для HTML-предпросмотра через `pypandoc`): [https://pandoc.org/installing.html](https://pandoc.org/installing.html)
- Опционально: LaTeX / Word / LibreOffice — для PDF-предпросмотра (см. сообщения на странице результата)

## Запуск веб-приложения

Из корня проекта:

```bash
python app.py
```

Откройте в браузере адрес, который выводит Flask (по умолчанию `http://127.0.0.1:5000`).

### Загрузка данных

На главной странице кнопка **«Начать»** — приложение само выполняет GET-запрос к API выгрузки. URL задаётся в `opop_defaults.json` (`api_get_json_url`) или переменной окружения `OPOP_API_GET_JSON_URL` (имеет приоритет). Пользователь URL не вводит.

## Как подготовить шаблон `template.docx`

1. Формат только **`.docx`** (не `.doc`).
2. Метки подстановки: `{{имя_поля}}`. Имена полей при сборке документа задаются в `json_data_extractor.build_opop_data`.

Примеры меток:

- `{{direction_code}}`
- `{{direction_name}}`
- `{{profile_full}}`

### Динамические таблицы (маркеры)

- `{{START_TABLE:universal}}` / `{{END_TABLE:universal}}` — таблица УК  
- `{{START_TABLE:professional}}` / `{{END_TABLE:professional}}` — таблица ОПК  
- `{{START_TABLE:prof_standards}}` / `{{END_TABLE:prof_standards}}` — профстандарты (область + стандарт)  
- `{{START_TABLE:pk}}` / `{{END_TABLE:pk}}` — ПК (тип задач + ПК + индикаторы)

Секции по областям и видам деятельности:

- профстандарты: `{{START_TABLE:prof_standards:06}}` … `{{END_TABLE:prof_standards:06}}`, то же для `:40`  
- ПК: `{{START_TABLE:pk:activity_1}}` … и для `activity_2`, `activity_3`

### Структурированные поля в `opop_data.json`

- `prof_standards_table`: массив объектов  
  `{ "area_code", "area", "standard", "generalized_functions" }`
- `pk_table`: массив объектов  
  `{ "task_type_key", "task_type", "pk_code", "pk_description", "indicators" }`

### Ручной ввод (`{{MANUAL:имя}}`)

Метки вида `{{MANUAL:normative_docs}}` (латиница, цифры, подчёркивание). После генерации черновика в браузере показываются поля ввода; после сохранения значения попадают в `manual_fields` внутри `opop_data.json` и в итоговый `.docx`.

Важно: держите каждую метку `{{MANUAL:…}}` **целиком в одном абзаце или ячейке**, иначе Word может разорвать метку на несколько run и подстановка не сработает.

### Подписи из БД (`{{IMAGE:имя}}`)

Подписи заведующего кафедрой и декана подставляются из выгрузки API (поле `signature` у сотрудника, base64 или `data:image/png;base64,...`). В `opop_data.json` они лежат в `employee_signatures`:

- `first_responsible` — заведующий кафедрой (по `department.head_id`);
- `second_responsible` — декан (по `faculty.dean_id`).

В шаблоне **удалите заглушки-картинки** (вставленные фотографии подписей) и вместо них в отдельном абзаце или ячейке поставьте текстовые метки (без смешивания с ФИО в одном абзаце, если можно):

- `{{IMAGE:first_responsible}}` — на месте подписи первого ответственного;
- `{{IMAGE:second_responsible}}` — на месте подписи второго ответственного.

Рядом по-прежнему можно оставить текстовые метки `{{first_responsible_fio}}` и `{{second_responsible_fio}}` для ФИО.

Каждая метка `{{IMAGE:…}}` должна быть **целиком в одном абзаце** (как `{{MANUAL:…}}`). Ширина картинки по умолчанию — 3,5 см (константа `_DEFAULT_SIGNATURE_WIDTH_CM` в `generate_opop.py`).

**PDF** на финальной странице создаётся по кнопке, не автоматически.

## Офлайн-генерация без Flask

Используйте `opop_data.json`, созданный веб-приложением в `instance/results/<job_id>/`:

```python
from generate_opop import generate_opop_document

generate_opop_document(
    template_path="template.docx",
    data_path="instance/results/<job_id>/opop_data.json",
    output_path="ОПОП.docx",
)
```

## Ограничения текущей версии

- Замена выполняется в основном тексте и в таблицах документа.
- Сложное смешанное форматирование в одной ячейке с меткой может упроститься при подстановке.
- Колонтитулы, надписи и часть нетекстовых элементов Word не обрабатываются.

## Рекомендации

- Держите метки в отдельных абзацах/ячейках без лишнего смешанного оформления рядом с ними.
- Для сложных шаблонов со смешанным форматированием часто используют `docxtpl` (в этом проекте не подключён).
