# Генерация документа ОПОП из Word-шаблона

Небольшой учебный проект: **генерация документа ОПОП** на основе шаблона Word (`.docx`) и тестовых данных из Python-словаря.

## Что в проекте

- `template.docx` — Word‑шаблон. В тексте и таблицах используются метки вида `{{key}}`.
- `opop_data.py` — тестовые данные `OPOP_DATA` (словарь `ключ -> строка`) для подстановки в шаблон.
- `generate_opop.py` — скрипт, который открывает шаблон, заменяет метки и сохраняет готовый документ.

## Требования

- Python 3.9+ (проект проверялся и на Python 3.13)
- Зависимость:

```bash
pip install python-docx
```

## Как подготовить шаблон `template.docx`

1. Шаблон должен быть **именно `.docx`** (не `.doc`).
2. В нужных местах вставьте метки вида `{{ключ}}`, где `ключ` — это имя поля из `opop_data.py`.

Примеры меток:

- `{{direction_code}}`
- `{{direction_name}}`
- `{{profile_full}}`

Полный список ключей смотрите в `opop_data.py` (словарь `OPOP_DATA`).

## Как сгенерировать документ

Запуск из папки проекта:

```bash
python generate_opop.py
```

По умолчанию:

- входной шаблон: `template.docx`
- выходной файл: `ОПОП-ПМ_тестовый.docx`

Если нужно указать пути программно, используйте функцию:

```python
from generate_opop import generate_opop_document

generate_opop_document(
    template_path="template.docx",
    output_path="ОПОП-ПМ_тестовый.docx",
)
```

## Ограничения текущей версии

- Замена выполняется **в тексте документа и в таблицах**.
- При замене через `paragraph.text = ...` / `cell.text = ...` Word может **потерять часть форматирования** (например, смешанный жирный/обычный текст в том же абзаце/ячейке).
- Не обрабатываются колонтитулы (header/footer) и некоторые “нетекстовые” элементы Word (надписи/textbox и т. п.).

## Быстрые рекомендации

- Если важно сохранить сложное форматирование рядом с метками, старайтесь держать метки в отдельных абзацах/ячейках без смешанного оформления.
- Для “богатых” подстановок (часть значения жирным, часть обычным) обычно переходят на `docxtpl` (пока не используется в этом проекте).
